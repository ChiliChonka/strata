# ADR-0012: A Themed Shell, and Notifications Served by Quickshell

## Status

Accepted

## Context

Two things were true of the Strata desktop after Phase 2, and they turned out to
be the same problem.

**It had no identity.** ADR-0004 reserves the right to a visual identity and
BRANDING.md describes what it should look like — layers, structure, clarity,
restraint — but the only thing implemented was a 28-pixel bar with four grey
labels, a black root window, and every other component wearing its upstream
defaults. A terminal, a launcher, a lock screen and a bar from four different
projects do not become a desktop by being installed together.

**The shell could not do what a laptop needs.** The bar showed volume and
battery. It could not change either. There was no way to see a network, adjust
brightness, reach the session's own power actions, or find a window that was
open on another workspace. Every one of those is a thing people reach for with
the mouse several times a day, and every one of them required a terminal.

Notifications were a third, smaller problem that constrains the first two.
ADR-0009 selected `mako-notifier`, and left open "whether Quickshell should
eventually replace `mako-notifier` and `hyprpolkitagent` natively". Only one
process can own `org.freedesktop.Notifications` on the session bus. As long as
mako holds it, the shell can neither style a notification nor keep a history of
them, and mako's own styling is a second theme to maintain in a second
configuration language.

The constraint on all of this is ADR-0003 and AGENTS.md: *minimal core*, and
"do not build a large widget suite for the MVP".

## Decision

**1. The shell owns the desktop's appearance.**

`/etc/xdg/quickshell/` becomes a small structured configuration rather than a
single file:

```text
theme.js     every colour, radius, size and duration
widgets/     the pieces the modules are built from
services/    what the shell reads from the system, instantiated once
modules/     the bar, its panels, the dock, the toasts and the OSD
```

`theme.js` is the single source of the palette. The Hyprland border colours, the
lock screen, the terminal and the launcher are configured to the same values, so
the desktop reads as one thing. The palette is cool stone in stacked planes
separated by hairlines, with one accent used only to mark state — the visual
language BRANDING.md asks for, and nothing more.

**2. The bar carries the controls a laptop actually needs.**

Workspaces, the focused window's title, the clock, notifications, network,
volume, brightness, battery and the session menu — each with a panel behind it
where a control is genuinely needed. Plus a dock of running applications, hidden
until the pointer reaches the bottom edge, and an on-screen display for the
volume and brightness keys.

**3. Quickshell serves notifications. mako is removed.**

`mako-notifier` leaves the package list. The shell runs the notification server,
shows toasts on the focused monitor, keeps them in a panel until dismissed, and
has a do-not-disturb switch that suppresses the interruption without discarding
the record.

**4. Icons are drawn, not shipped.**

The shell draws its dozen icons on a 24x24 grid in QML. No Nerd Font, no icon
theme, no new package, and no trademark question.

**5. Nothing project-specific is introduced to make this work.**

The backlight uses `brightnessctl` (40 KB, ships the udev rule that makes it
work unprivileged). The network uses `nmcli`, already installed. Sessions use
`systemctl` and logind's existing polkit rules. The wallpaper is generated by a
standard-library Python script in the repository and drawn by `hyprpaper`, which
was already in the package list and previously not started. One new file,
`/usr/lib/strata/lock`, exists so the keybinding, the session menu and hypridle
all produce the same lock screen and cannot stack two of them.

## Alternatives Considered

**Keep mako and theme it.** Rejected. It is a second theme in a second
configuration language, it cannot show a history, and it makes the shell a
spectator to the one part of the desktop that interrupts the user.

**Ship an icon font or icon theme.** Rejected. Tens of megabytes on the image
for a dozen glyphs, plus a licence question, to replace 200 lines of drawing
code.

**Adopt an existing shell configuration** — caelestia-shell and its relatives.
Rejected on ADR-0001 and ADR-0003 grounds: they are large, they assume packages
Debian does not have, and vendoring one would make Strata's desktop something
this project maintains a fork of rather than something it configures.

**Do nothing, on the grounds that AGENTS.md forbids a widget suite.** Rejected,
and this is the closest call in this record. See below.

## Consequences

### Positive

- the desktop has one palette, applied consistently across five components,
- volume, brightness, network, notifications, windows and session actions are
  reachable with the mouse, which is what "a functional desktop" means to
  everyone who did not write it,
- notifications are the shell's, so they can be styled, kept, and silenced,
- one fewer daemon in the session and one fewer package on the image,
- the wallpaper, the lock screen and the greeter no longer disagree about what
  Strata looks like.

### Negative

- **This is more shell than AGENTS.md's MVP wording invites.** It is a real
  cost, not a technicality. The defence is that ADR-0003 constrains the
  *package set* and the *installed footprint*, both of which go down here: one
  package removed, one 40 KB package added, no new daemon, no new framework, no
  new dependency. What grew is configuration in a language the image already
  runs. The line this record draws is that a control the desktop cannot
  otherwise reach is in scope, and everything else is not: there is no media
  player, no weather, no system monitor, no wallpaper switcher, and adding one
  is an argument to have against ADR-0003 first.
- roughly 1,700 lines of QML to maintain, against maybe 200 before,
- Quickshell API drift now breaks more than a clock. The services that depend on
  optional Quickshell modules are behind Loaders, so a missing one costs its
  feature rather than the session, but this is mitigation and not immunity,
- the bar polls: `nmcli` every four seconds, the backlight every two, the
  drop-in part directory every three. Each is one short-lived process. The
  Wi-Fi scan runs only while its panel is open, because that one is expensive,
- removing mako means a Quickshell that fails to start leaves the session with
  no notification daemon at all, where previously the two were independent. The
  live test therefore asserts that the bus name is actually owned, not merely
  that a process exists.

### Neutral

- greeter branding stays out of scope, exactly as AGENTS.md and TASKS.md
  Phase 5 require. `tuigreet` is untouched. Login reliability is not traded for
  appearance,
- a user who writes `~/.config/quickshell/shell.qml` still replaces all of this,
  and `~/.config/hypr/*.conf` still wins over every file shipped here.

## Supersedes

Resolves the open question in ADR-0009 for notifications: Quickshell replaces
`mako-notifier`. The `hyprpolkitagent` half of that question is untouched and
remains open — an authentication prompt is not a place to experiment.
