# ADR-0015: Ship Strata's Own Files as a Debian Package

## Status

Proposed.

## Context

Strata's own files — the bar, the session configuration, the `strata` and
`browser` commands, the component definitions, the theme generator — are 61
files, 464 kB, delivered by copying `config/includes.chroot` into the image at
build time. They belong to no package.

The consequence surfaced while fixing two bugs on an installed laptop: six files
were out of date and there was no way to update them. Not a slow way, not an
awkward way — none. `apt` does not know they exist, `dpkg -S` finds no owner,
and an installed system's only routes to a fix are copying files by hand or
reinstalling over the top.

That sits badly with [ADR-0001](ADR-0001-debian-not-a-fork.md), whose promise is
that an installed Strata is ordinary Debian. Ordinary Debian is a set of
packages that can be upgraded. A third of the desktop's behaviour arriving as
unowned files in `/etc` and `/usr` is the part that is not ordinary.

It also hides real problems. `/etc/xdg/fuzzel/fuzzel.ini` is a conffile owned by
the fuzzel package, and Strata overwrites it — recorded in
[ADR-0013](ADR-0013-typography-icons-and-one-colour-scheme.md) as a known cost.
A package would make that collision explicit instead of silent.

## Decision

Strata's files become a Debian package, `strata-desktop`, built from this
repository and installed into the image like any other package.

The image stops copying them in. `config/includes.chroot` keeps only what cannot
belong to a package.

**What this settles:** the files are owned. `dpkg -S` names them, `dpkg -V`
notices when they are edited, an upgrade replaces them, and a removal takes them
away. A fix can reach an installed machine.

**What this does not settle:** how the package gets there. That is a separate
decision and a heavier one — see below.

### The repository question is deliberately left open

The obvious next step is an APT repository, so `apt upgrade` picks Strata's
fixes up like everything else. [ADR-0011](ADR-0011-optional-components.md)
refuses third-party APT repositories, and the reason applies to Strata's own:

> An APT repository ships a signing key, and once that key is trusted it is
> trusted for *every package name*, including replacements for system
> components. It is a systemwide grant.

That argument does not weaken because the repository would be ours. A Strata
repository key could ship a `bash`. Refusing Brave's repository and then asking
for the same grant for ourselves would be the kind of exception that makes the
original reasoning worthless.

There are answers — apt supports restricting a source to named packages, and a
release could be a signed `.deb` on GitHub with no repository at all — but
choosing between them is a decision about distribution and trust, not about
packaging. It gets its own record. Until then the package is built and installed
into the image, and updating an installed system means fetching one `.deb`.

### What stays outside the package

The live-config components — `2000-strata-greetd-autologin` and
`2010-strata-hypridle-live` — configure autologin and suppress idle locking for
a session whose password nobody was told. Both already refuse to act unless
`/run/live/medium` exists, so packaging them is harmless, and it is one fewer
mechanism. They go in.

`/etc/strata/theme/` is generated by `apply-theme` and must not be package
content: dpkg would fight the generator over files it rewrites on every theme
change. The generator is packaged; its output is not.

## Consequences

### Positive

- an installed system can be fixed without reinstalling it,
- the files have an owner, a version, and a changelog,
- `dpkg -V` reports what a user has modified, which is a real diagnostic,
- the fuzzel conffile collision becomes visible at build time.

### Negative

- **The build grows a packaging step.** live-build installs a local `.deb`,
  which means building one before building the image, and keeping the two in
  step.
- **Conffile prompts.** Files under `/etc` in a package prompt on upgrade when
  the user has edited them. That is correct behaviour and it is still a worse
  first impression than a file quietly changing. Everything under `/etc` needs
  deciding: conffile, or generated, or moved to `/usr/share` with an override
  path.
- **A version scheme.** Images are dated; packages need versions that sort. The
  two are not the same thing and pretending they are will hurt later.
- Until the repository question is answered, updating means downloading a file,
  which is barely better than copying six.

### Deferred

How the package reaches a machine — signed `.deb` per release, an APT
repository restricted to Strata's own package names, or something else. That
record has to weigh the same trust argument ADR-0011 used against Brave, and
apply it to us.

## Guiding Principle

If an installed Strata is ordinary Debian, then Strata's own files are an
ordinary Debian package, and fixing them is an ordinary upgrade.
